# 《异环·即刻落槌》本地 Web 复刻：基础功能设计文档

## 1. 背景与目标

参考《异环》“即刻落槌”玩法，设计一个本地 Web 版本，用于原型验证、玩法学习或本地多人演示。

目标不是完整复刻线上游戏，而是还原核心循环：**盲盒藏品 → 情报探测 → 多回合竞价 → 买断/价高者得 → 盈亏结算 → 分红与资产成长**。

本地 Web 版本优先采用单设备、本地存储实现，不依赖后端服务；后续如需多人联机，可再扩展 WebSocket 房间服务。

## 2. 核心玩法抽象

每局流程如下：

1. 玩家选择会场，扣除入场费，获得初始资产。
2. 系统生成一批未知藏品，包含品质、轮廓、尺寸、真实价值等信息。
3. 玩家选择竞拍帮手和仪器组合，逐步获得藏品情报。
4. 每回合玩家出价，系统模拟其他玩家出价。
5. 若最高出价达到买断阈值，提前成交；否则进入第 5 回合价高者得。
6. 若第 5 回合最高价相同，进入第 6 回合加赛；再次相同则流拍。
7. 成交后结算盈亏；若买家亏损，其他玩家获得亏损额 10% 的分红。

## 3. 功能模块划分

| 模块 | 功能 | 说明 |
| ------ |------ |------ |
| 资产与会场 | 初始资金、入场费、低保金 | 支持海贝场、珊瑚场、真珠场 |
| 藏品生成 | 随机生成藏品 | 包含品质、轮廓、尺寸、真实价值 |
| 情报系统 | 帮手、仪器、公开情报 | 逐步揭示藏品信息 |
| 竞价系统 | 6 回合出价与买断判定 | 支持提前买断、加赛、流拍 |
| 结算系统 | 盈亏计算、分红、藏品处理 | 支持出售或放入展览柜 |
| 本地数据 | 存档、图鉴、排行榜 | 使用 LocalStorage 或 IndexedDB |
| 界面交互 | 仓库视图、出价面板、日志 | 强调信息不完全与风险提示 |

## 4. 数据模型设计

### 4.1 玩家资产

```ts
interface PlayerAsset {

```

初始资金可设为 3,000,000。

### 4.2 会场配置

```ts
interface Venue {
  id: "shell" | "coral" | "pearl";
  name: string;
  assetRequirement: number;
  entryFee: number;
  rarityWeight: Record<string, number>; // 不同品质出现权重

```

参考配置：

- 海贝场：无资产要求，无入场费。
- 珊瑚场：资产不少于 1,000,000，入场费 5,000。
- 真珠场：资产不少于 5,000,000，入场费 20,000。

### 4.3 藏品

```ts
interface CollectionItem {
  id: string;
  name: string;
  quality: "gray" | "blue" | "purple" | "gold" | "red";

    outline: boolean;

```

藏品信息默认隐藏，仅通过帮手、仪器或公开情报逐步揭示。


## 5. 竞价规则实现

### 5.1 回合数

常规最多 5 回合。若第 5 回合出现相同最高价，则进入第 6 回合。

### 5.2 买断判定

第 1-4 回合中，若最高出价高于第二名达到对应倍数，可直接买断全部藏品。

倍数规则可配置为：

| 回合 | 买断倍数 |
| ------ |------ |
| 1 | > 2.0 倍 |
| 2 | > 1.6 倍 |
| 3 | > 1.3 倍 |
| 4 | > 1.1 倍 |
| 5 | 不买断，价高者得 |

注意：第 1 回合需要“高于第二名 2 倍”，不是“大于等于 2 倍”。

### 5.3 第 6 回合

若第 5 回合最高价相同，则进入第 6 回合加赛；第 6 回合出价不得低于第 5 回合最高价；若再次相同则流拍。

### 5.4 弃权规则

玩家在某回合未出价，则视为弃权，本局后续不可再出价。

本地版本中，可简化为：每回合必须确认出价或主动放弃。

## 6. 情报系统设计

### 6.1 公开情报

第 1、3 回合提供公开情报，例如：

- 展示部分藏品轮廓；
- 提示某类品质数量；
- 提示当前场地条件。

### 6.2 竞拍帮手

帮手提供不同情报技能，例如：

- 展示藏品轮廓；
- 展示藏品品质；
- 展示高价值藏品数量；
- 在特定回合揭示更多藏品信息。

本地版本中，帮手可抽象为“情报策略卡”，每局选择一个，影响每回合可获得的提示。

### 6.3 仪器组合

仪器在局外购买，局内每回合使用一个。未用完的仪器可带出；购买新组合后旧组合剩余仪器废弃。

仪器类型可包括：

- 估值仪器：估算某类藏品总价值；
- 轮廓仪器：显示部分藏品轮廓；
- 品质仪器：显示部分藏品品质；
- 排除仪器：排除低价值藏品范围；
- 尺寸仪器：显示藏品占用格数。

## 7. 结算与收益规则

成交后，买家获得全部藏品。

结算方式：

```ts
profit = totalRealValue - finalPrice - entryFee
```

若买家亏损，其余玩家各获得亏损额的 10% 作为奖励。

藏品处理：

- 直接出售：立即获得金贝铢；
- 放入展览柜：按时间获得持续收益，可优先展示高价值红色藏品。

本地版本中，展览柜收益可按“每局结束结算一次”简化，不必实现真实时间挂机。

## 9. 页面流程

1. **首页**：显示当前资产、图鉴、历史战绩。
2. **选择会场**：检查资产门槛，扣除入场费。
3. **局前准备**：选择帮手、购买仪器、确认初始资金。
4. **竞拍房间**：展示藏品仓库、情报面板、出价输入、回合日志。
5. **结算页**：展示真实藏品、盈亏、分红、藏品处理选项。
6. **图鉴页**：记录已见藏品轮廓、品质、名称和价值区间。

## 10. 交互设计要点

- 藏品默认不显示真实价值；
- 出价后不可撤销；
- 每回合需显示当前最高价、第二名价格、买断阈值；
- 玩家输入出价时提示“是否确认”，避免误操作；
- 亏损分红需明确展示，强化博弈感；
- 第 6 回合需明确提示“加赛”和“不得低于上回合最高价”。

## 11. AI 对手设计

本地版本可用简单机器人模拟其他玩家。

机器人策略可包括：

- 保守型：低价试探，避免亏损；
- 估值型：根据已知情报估算总价值；
- 激进型：早期抬价，试图诱导玩家亏损；
- 分红型：故意放弃，等待买家亏损后获得分红。

机器人出价逻辑可简化为：

```ts
estimatedValue = sum(revealedItems.estimatedValue) + hiddenBonus
maxBid = estimatedValue * riskFactor
```

## 12. 本地存储设计

使用 LocalStorage 保存：

- 玩家资产；
- 藏品图鉴；
- 历史对局；
- 赛季统计；
- 仪器库存；
- 展览柜藏品。

数据结构示例：

```json
{
  "player": { ... },
  "collections": [ ... ],
  "history": [ ... ],
  "season": {
    "cycleDays": 60,
    "startAt": "2026-10-09",
    "profitRank": [ ... ]
  }
}
```

赛季排名可本地模拟，不强制实现全服排行。

## 13. 可扩展方向

- 增加 WebSocket 房间，实现真实多人联机；
- 增加更多场地条件，如“天黑了”“价值翻倍”“闪耀之心”；
- 增加更多帮手和仪器组合；
- 增加藏品图鉴解锁进度；
- 增加资产曲线和盈亏统计；
- 增加导出对局记录功能，便于复盘。

## 14. 风险与边界

- 不实现真实货币交易；
- 不实现全服排行榜；
- 不实现实时挂机收益；
- 机器人行为仅用于本地演示；
- 数值配置应可调整，便于后续平衡。

该版本适合先实现最小可玩原型：单玩家、三会场、随机藏品、6 回合竞价、买断判定、盈亏结算、分红机制、本地存档。后续再逐步补充图鉴、赛季、机器人策略和联机能力。
